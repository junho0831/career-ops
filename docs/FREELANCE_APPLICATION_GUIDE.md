## 1. 절대 원칙: 100% 원격(재택) 필수 / 상주 근무 절대 불가

> [!CAUTION]
> **외주 프로젝트는 '100% 원격(재택) 근무'만 지원하며, 상주 근무는 절대 불가합니다.**

> - "원격 선호/원격 가능", "주 1회 이하 미팅(협의 가능)", "100% 재택" 프로젝트에만 지원합니다.

## 2. 핵심 원칙: 비개발자 클라이언트 관점의 글쓰기

> [!IMPORTANT]
> **"클라이언트는 개발자가 아닙니다!"**
> - 외주를 맡기는 고객(대표님, 사업팀, 운영 담당자)은 어려운 컴퓨터 공학 용어(MVCC, Lua Script, Server-side Cursor, ZSET 등)를 모릅니다.
> - **'어떤 기술을썼는가'보다 '내 사업/서비스의 문제가 어떻게 해결되고 결과가 어떠한가'**가 1순위 관심사입니다.
> - 복잡한 개발 용어는 **클라이언트가 얻는 실질적 혜택(속도 개선, 서버 다운 방지, 비용 절감, 데이터 유실 0%)**으로 번역해서 전달해야 합니다.
> - 단, 제안서에 담기는 모든 문제 해결 경험은 100% [`cv.md`](file:///home/junho/IdeaProjects/career-ops/cv.md)의 사실에 기반해야 합니다.

## 3. 현재 설치된 `browsermcp` 연동 제어 원칙
 
> [!WARNING]
> **우회 러너 스크립트, 파이썬 매크로 및 DevTools 콘솔 조작 일체 금지**
> - 지원 전 과정은 사용자 환경에 공식 연동되어 설치된 **`browsermcp`** MCP 도구(`call_mcp_tool` -> `ServerName: "browsermcp"`)만을 직접 호출하여 브라우저를 조작합니다.
> - `run_command`를 통한 임의의 래퍼(`node browsermcp-runner.cjs`), 셸 스크립트, 파이썬 매크로, DevTools 콘솔 주입은 전면 금지됩니다.
> 1. `browser_snapshot`: 페이지 텍스트, 입력 폼 요소(`textarea`, `input`), 버튼 ref 식별
> 2. `browser_type`: 제안 금액, 예상 기간, 제안서 본문 입력
> 3. `browser_click`: 관련 이력서/포트폴리오 선택 및 `지원하기` 버튼 클릭
> 4. `browser_wait`: 페이지 로딩 및 저장 완료 대기
> 5. `browser_screenshot`: 화면 렌더링 및 모달 상태 시각적 검증

## 5. 플랫폼별 제안 핵심 포인트

### 1) 위시켓 (Wishket)
- **주요 고객**: IT 스타트업 대표, 서비스 기획자, 초기 창업자
- **근무 형태 필터링**: '상주' 요구 프로젝트는 즉시 패스, '원격' 프로젝트만 지원.
- **`browsermcp` 액션**:
  - 지원서 폼 페이지에서 `browser_snapshot`으로 지원 금액, 작업 기간, 지원서 입력 영역의 ref 획득.
  - 비개발자 맞춤형 제안서 내용을 `browser_type`으로 입력 후 `제출` 클릭.
- **공략 포인트**:
  - **공감과 안심**: "기획하신 서비스가 오픈 후 먹통이 되지 않도록 튼튼하게 설계해 드립니다."
  - **현실적 제안**: 비현실적인 일정이면 안 된다고만 하지 않고, "오픈 일정을 맞추기 위해 1차 오픈 핵심 기능(MVP)을 먼저 안정화하고 2차로 고도화하는 방향을 추천드립니다."와 같이 대안 제시.

### 2) 프리모아 (Freemoa)
- **주요 고객**: 중소기업 대표, 제조업/유통업 총괄, 정부지원사업 수행 기업
- **근무 형태 필터링**: '상주/파견' 조건 프로젝트 제외, '재택/원격' 프로젝트만 선별.
- **`browsermcp` 액션**:
  - 제안서 폼 모달/페이지에서 `browser_snapshot`으로 이력서 선택 라디오 버튼, 지원 내용, 견적 입력란 식별.
  - 최적 포트폴리오를 `browser_click`으로 선택하고 제안 내용 입력 후 제출.
- **공략 포인트**:
  - **안정성과 프로세스**: "기존 엑셀/수작업 데이터를 안전하게 이관하고, 현장 담당자가 쉽게 쓸 수 있는 직관적인 관리자 기능을 구축해 드립니다."
  - **인수인계 보장**: "개발 완료 후 상세한 매뉴얼과 함께 직접 시연하며 설명해 드리므로 안심하고 운영하실 수 있습니다."

## 6. 클라이언트 미팅을 성사시키는 실전 고합격 제안서 프레임워크 (5대 핵심 킬러 구성)

경쟁자가 40~130명 몰리는 플랫폼에서 **완료 평가 수가 적은 개인 파트너가 무조건 미팅을 따내기 위한 4대 치트키 원칙**:
1. **첫 3줄 킬러 훅(Hook)**: 어려운 스펙 나열(Lua Script, 1,973만 건 등) 대신, 클라이언트 공고의 진짜 아픈 점(주문 꼬임, 데이터 유실, 관리자 부재)을 콕 집어 해결 확신 제시.
2. **비개발자 운영 안심 장치**: "개발자 없이 대표님이 직접 쓰는 관리자 화면", "화면 캡처 10페이지 운영 매뉴얼", "납품 후 1개월 무상 하자보수 보증".
3. **가벼운 시작(PoC/MVP) 제안**: 전체 계약 전 핵심 1개 모듈을 1~2주 가볍게 검증해보고 결정할 수 있는 파격적 안심 옵션 제공.
4. **눈에 보이는 작동 데모 연결**: 코드나 깃허브보다 직관적인 실제 웹 동작 서비스(`so-dak.com`) 직접 체험 유도.

### [표준 고합격 제안서 템플릿]

```markdown
대표님(담당자님), 공고에 적어주신 [핵심 문제: 예 - 주문 누락/데이터 꼬임/관리자 화면 부재] 문제 정확히 확인했습니다.
현장에서 데이터 유실이나 꼬임 없이 100% 매끄럽게 돌아가도록 구축하고, 개발자 없이도 대표님이 직접 품목과 설정을 바꾸실 수 있는 쉬운 관리자 화면까지 정해진 일정 내에 완성해 드리겠습니다.
(본 프로젝트는 100% 원격/재택으로 진행되며, 매주 테스트 가능한 화면을 직접 보여드리며 투명하게 소통합니다.)

[1. 클라이언트님의 핵심 고민 및 해결 방안]
- 공고 분석: [클라이언트가 만들고자 하는 서비스와 현장의 가장 큰 걱정거리 1줄 요약]
- 확실한 해결책:
  1) [결과물 안정성]: 동시 접속이나 네트워크가 끊기는 상황에서도 데이터가 꼬이거나 날아가지 않는 안전한 이중 잠금 설계.
  2) [운영 편의성]: 문제 발생 시 매번 개발자를 찾을 필요 없이, 관리자 화면에서 클릭 한 번으로 오류를 조회하고 즉시 바로잡는 관리자 기능 제공.

[2. 안심하고 맡기실 수 있는 3단계 실행 계획]
- 1단계 (핵심 로직 & 화면 시연 / 약 2~3주): 핵심 기능이 실제로 돌아가는 프로토타입을 만들어 대표님께 먼저 시연해 드립니다.
- 2단계 (관리자 시스템 & 연동 완성 / 약 2~3주): 대표님과 실무진이 쓰실 웹 어드민 화면 및 데이터 연동을 마칩니다.
- 3단계 (현장 최종 검증 & 배포 / 약 1~2주): 실제 환경에서 예외 상황을 꼼꼼히 테스트하고 정식 오픈합니다.
💡 [부담 없는 옵션]: 전체를 한 번에 계약하기 부담스러우시다면, 핵심 [OO 연동] 1차 검증(1~2주)을 먼저 가볍게 진행해 보신 뒤 최종 본계약을 결정하셔도 좋습니다!

[3. 유사 서비스 구축 및 문제 해결 실적 (100% 검증된 사실 기반)]
클라이언트님의 프로젝트와 똑같은 문제를 실제로 해결한 경험입니다:
- [실시간 동시 처리 및 꼬임 방지]: 수많은 사용자가 동시에 버튼을 누르거나 주문을 넣어도 순서대로 안전하게 처리되는 시스템을 1인으로 직접 설계·운영한 실적이 있습니다.
- [대용량 데이터 누락 0%]: 약 2천만 건 규모의 대규모 데이터를 다루며, 도중에 에러가 나더라도 데이터가 유실되지 않고 멈춘 지점부터 자동 복구되는 무결성 파이프라인을 운영했습니다.
- [금융/결제 수준의 정합성 관리]: 결제 및 거래 데이터에서 단 1건의 오차도 발생하지 않도록 오류 0건을 유지하며 관리자 원클릭 재처리 기능을 직접 구축했습니다.

[4. 비개발자 클라이언트를 위한 3대 안심 약속]
1. [매주 눈으로 확인하는 진행 상황]: 어려운 개발 용어 대신, 매주 직접 스마트폰과 PC에서 눌러보실 수 있는 테스트 링크를 제공합니다.
2. [10페이지 캡처 운영 매뉴얼 제공]: 비개발자 담당자도 10분 만에 익힐 수 있는 화면 캡처 매뉴얼과 직접 시연 설명을 함께 전달합니다.
```
