## 1. 절대 원칙: 100% 원격(재택) 필수 / 상주 근무 절대 불가

> [!CAUTION]
> **외주 프로젝트는 '100% 원격(재택) 근무'만 지원하며, 상주 근무는 절대 불가합니다.**
> - 공고 내용에 **"상주 필수", "파견 근무", "주 N일 본사 출근/상주"** 조건이 명시된 프로젝트는 **필터링 단계에서 즉시 제외(지원 불가)**합니다.
> - "원격 선호/원격 가능", "주 1회 이하 미팅(협의 가능)", "100% 재택" 프로젝트에만 지원합니다.
> - 제안서 서두 또는 협업 방식에 원격 기반의 투명한 소통 방식(Slack, 게더, 정기 온라인 미팅)을 명시하여, 비상주라도 전혀 불안하지 않도록 신뢰를 줍니다.

## 2. 핵심 원칙: 비개발자 클라이언트 관점의 글쓰기

> [!IMPORTANT]
> **"클라이언트는 개발자가 아닙니다!"**
> - 외주를 맡기는 고객(대표님, 사업팀, 운영 담당자)은 어려운 컴퓨터 공학 용어(MVCC, Lua Script, Server-side Cursor, ZSET 등)를 모릅니다.
> - **'어떤 기술을썼는가'보다 '내 사업/서비스의 문제가 어떻게 해결되고 결과가 어떠한가'**가 1순위 관심사입니다.
> - 복잡한 개발 용어는 **클라이언트가 얻는 실질적 혜택(속도 개선, 서버 다운 방지, 비용 절감, 데이터 유실 0%)**으로 번역해서 전달해야 합니다.
> - 단, 제안서에 담기는 모든 문제 해결 경험은 100% [`cv.md`](file:///home/junho/IdeaProjects/career-ops/cv.md)의 사실에 기반해야 합니다.

## 3. 현재 설치된 `browsermcp` 연동 제어 원칙

> [!WARNING]
> **파이썬 스크립트(x11/매크로) 및 DevTools 콘솔 조작 일체 금지**
> - 지원 전 과정은 사용자 환경에 공식 연동되어 설치된 **`browsermcp`** MCP 서버를 통해서만 브라우저를 조작합니다.
> 1. `browser_snapshot`: 페이지 텍스트, 입력 폼 요소(`textarea`, `input`), 버튼 ref 식별
> 2. `browser_type`: 제안 금액, 예상 기간, 제안서 본문 입력
> 3. `browser_click`: 관련 이력서/포트폴리오 선택 및 `지원하기` 버튼 클릭
> 4. `browser_wait`: 페이지 로딩 및 저장 완료 대기

## 5. 플랫폼별 제안 핵심 포인트

### 1) 위시켓 (Wishket)
- **주요 고객**: IT 스타트업 대표, 서비스 기획자, 초기 창업자
- **근무 형태 필터링**: '상주' 요구 프로젝트는 즉시 패스, '원격' 프로젝트만 지원.
- **`browsermcp` 액션**:
  - 지원서 폼 페이지에서 `browser_snapshot`으로 지원 금액, 작업 기간, 지원서 입력 영역의 ref 획득.
  - 비개발자 맞춤형 제안서 내용을 `browser_type`으로 입력 후 `제출` 클릭.
- **공략 포인트**:
  - **공감과 안심**: "기획하신 서비스가 오픈 후 먹통이 되지 않도록 튼튼하게 설계해 드립니다."
  - **현실적 제안**: 비현실적인 일정이면 안 된다고만 하지 않고, "오픈 일정을 맞추기 위해 1차 오픈 핵심 기능(MVP)을 먼저 안정화하고 2차로 고도화하는 방향을 추천드립니다."와 같이 대안 제시.

### 2) 프리모아 (Freemoa)
- **주요 고객**: 중소기업 대표, 제조업/유통업 총괄, 정부지원사업 수행 기업
- **근무 형태 필터링**: '상주/파견' 조건 프로젝트 제외, '재택/원격' 프로젝트만 선별.
- **`browsermcp` 액션**:
  - 제안서 폼 모달/페이지에서 `browser_snapshot`으로 이력서 선택 라디오 버튼, 지원 내용, 견적 입력란 식별.
  - 최적 포트폴리오를 `browser_click`으로 선택하고 제안 내용 입력 후 제출.
- **공략 포인트**:
  - **안정성과 프로세스**: "기존 엑셀/수작업 데이터를 안전하게 이관하고, 현장 담당자가 쉽게 쓸 수 있는 직관적인 관리자 기능을 구축해 드립니다."
  - **인수인계 보장**: "개발 완료 후 상세한 매뉴얼과 함께 직접 시연하며 설명해 드리므로 안심하고 운영하실 수 있습니다."

## 6. 비개발자용 표준 제안서 3단계 템플릿

```markdown
안녕하세요, 클라이언트님의 서비스를 내 사업처럼 안정적으로 구현해 드릴 백엔드 엔지니어 박준호입니다.
(본 프로젝트는 100% 원격/재택으로 진행되며, 일일/주간 단위로 투명하고 긴밀하게 소통합니다.)

[1. 프로젝트 요구사항 이해 및 해결 방향]
남겨주신 [프로젝트명/핵심 기능] 내용을 꼼꼼히 확인했습니다.
현재 가장 중요하게 생각하시는 부분은 [예: 사용자가 몰려도 멈추지 않는 안정적인 서비스 / 복잡한 데이터가 꼬이지 않고 정확하게 처리되는 시스템]이라고 생각합니다.
화려한 기술보다는 실제 고객이 이용할 때 불편함이 없고, 관리자분께서 운영하기 편안한 구조로 개발해 드리겠습니다.

[2. 유사 경험 및 문제 해결 사례]
제가 참여했던 실제 프로젝트 중 본 과제에 바로 적용할 수 있는 경험들입니다:

- [사례 1: 대용량/속도 개선이 필요한 경우]
  수천만 건의 데이터를 다루는 시스템에서 데이터 처리 시간을 30% 이상 단축시키고, 중간에 오류가 나더라도 데이터가 유실되지 않고 안전하게 재실행되는 안정적인 데이터 처리 파이프라인을 구축한 경험이 있습니다.

- [사례 2: 동시 접속/실시간 서비스인 경우]
  수많은 사용자가 동시에 몰려도 데이터가 중복되거나 서버가 지연되지 않도록, 대규모 동시 접속 환경을 1인으로 직접 설계하고 실서비스로 운영해 보았습니다.

- [사례 3: 관리자 페이지/업무 자동화인 경우]
  개발자를 거치지 않고도 담당자분께서 관리자 화면에서 직접 데이터를 확인하고 수정/재처리할 수 있는 운영 편의 기능을 구축해 정합성 오류를 0건으로 낮춘 경험이 있습니다.

[3. 일정 및 원격 안심 협업 약속]
- 원격 소통: 기술 용어로 어렵게 설명하지 않고, Slack/게더/전화 등을 통해 일상적인 언어로 진행 상황을 매일/매주 투명하게 공유해 드립니다.
- 단계별 검증: 일방적으로 만들고 끝내는 것이 아니라, 중간 개발 단계마다 직접 테스트해보실 수 있는 화면을 제공해 드립니다.
- 확실한 인수인계: 납품 후에도 관리자분께서 혼자서 손쉽게 운영하실 수 있도록 꼼꼼한 사용 가이드를 제공해 드립니다.
```
